# Frontend minimatch security alert

Owner: Liu Tongyao (@cpg25ncu) · Requirement: conversation task of 2026-11-04 to clear Dependabot alert #14, no Issue number · Branch: `fix/liu-tongyao-minimatch-alert` · Baseline: `3740a83fb670f44a03e436b7be78cffd0240dcc6` (`origin/main`)

## 2026-11-04 Override minimatch to 11.x

### What was built

Cleared Dependabot alert #14 (medium): GHSA-g3hv-75wg-m249, "minimatch has potential denial of service via globparts amplification". The alert covers `minimatch` < 11.0.1, a development-only transitive dependency in `frontend/pnpm-lock.yaml`.

| Version before | Required by |
| --- | --- |
| 3.1.5 | `eslint` 9.39.5, `@eslint/config-array` 0.21.2, `@eslint/eslintrc` 3.3.7 |
| 5.1.9 | `@redocly/openapi-core` 1.34.20 (through `openapi-typescript`) |
| 10.2.6 | `@typescript-eslint/typescript-estree` 8.70.1 |

`frontend/pnpm-workspace.yaml` now overrides `minimatch` to `^11.0.1`. The lockfile resolves all five dependents to `minimatch` 11.0.4, which brings `brace-expansion` 5 and `@isaacs/nonrecursive-glob-match`. Changed files: `frontend/pnpm-workspace.yaml`, `frontend/pnpm-lock.yaml` and this entry. Application code, tests and workflows are unchanged.

### Design notes

No smaller fix exists:

- the advisory has one patched version, 11.0.1;
- the latest 3.x, 5.x and 10.x releases (3.1.5, 5.1.9, 10.2.6) predate it;
- no current release of the dependents requires minimatch 11, as of 2026-11-04:

  | Package | Release | minimatch range |
  | --- | --- | --- |
  | `eslint` | 9.39.5; 10.14.0 | `^3.1.5`; `^10.2.6` |
  | `@eslint/config-array` | 0.23.5 | `^10.2.4` |
  | `@typescript-eslint/typescript-estree` | 8.72.1 | `^10.2.2` |
  | `@redocly/openapi-core` | 1.34.23 | `5.1.9` |

Dependabot's own security update for this alert failed on 2026-11-04 for the same reason.

minimatch 9 and later export named functions only, so `require('minimatch')` returns an object, not a function. Each dependent was checked for that:

| Dependent | Use of minimatch | Effect of 11.x |
| --- | --- | --- |
| `eslint`, `@eslint/config-array` (flat config) | `minimatch.Minimatch` | None |
| `@eslint/eslintrc` | Calls the default export | Used only by legacy `.eslintrc` configs; this project uses flat config |
| `@redocly/openapi-core` | Calls the default export in `match()` inside `readFileFromUrl` | Runs only when redocly fetches a URL with `resolve.http.headers` configured. `scripts/gen-api.mjs` fetches the schema itself and passes the parsed object to `openapi-typescript` |
| `@typescript-eslint/typescript-estree` | Named imports, written for 10.x | None |

The comment in `pnpm-workspace.yaml` points here. Remove the override once the dependents require minimatch 11.

### Problems and fixes

| Symptom | Root cause | Fix | How it was verified |
| --- | --- | --- | --- |
| Alert #14 stayed open; Dependabot's security update run failed | All dependents pin minimatch ranges below 11, and the older lines have no fix | `pnpm` override to `^11.0.1` | Lockfile contains only `minimatch@11.0.4` |
| A broken matcher could make ESLint pass while checking nothing | `require('minimatch')` changes shape in 11.x | Compared ESLint before and after with a probe file holding one unused variable | Both runs: 102 files, the same single `@typescript-eslint/no-unused-vars` error, byte-identical `--print-config` for `src/main.tsx` and `vite.config.ts`; probe file removed |
